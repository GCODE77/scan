## B. 외부 주장 재확인

직접 재확인한 것

* Firebase Storage: 공식 FAQ(https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024, 2026-11-16 확인)에서 "2026-02-03부터 Spark 프로젝트는 Cloud Storage 읽기·쓰기 접근을 잃는다"와 "새 기본 버킷은 Blaze 필요"를 확인. research.md의 "2024-10-30" 날짜는 이번에 가져온 페이지 요약에서 확인하지 못했다(틀렸다는 뜻은 아님).
* Google OAuth: https://developers.google.com/identity/protocols/oauth2 에서 '테스트' 상태 앱의 갱신 토큰이 7일 만에 만료된다는 문장 확인. 기본 신원 범위(email, profile, openid)만 쓰면 예외. `drive.file`은 예외가 아니므로 research.md:108 위험 기술은 맞다.
* Dropbox PKCE: 공식 oauth-guide 페이지는 접속 오류로 못 읽었다. Dropbox 포럼 직원 답변과 마이그레이션 글(https://dropbox.tech/developers/migrating-app-permissions-and-access-tokens)로 `token_access_type=offline` + PKCE면 비밀키 없이 갱신 토큰 사용이 가능함을 간접 확인. 공식 문서 직접 확인은 못 했다.
* ML Kit 번역 비용: 재확인 못 했다.

1. (중간) research.md:27, :29, :43 비용 열 "Dropbox API 무료 확인". 같은 문서 §5(research.md:107)는 카드 등록 "미확인", 비활동 정지 "근거 못 찾음", 정책 변경 "미확인"이다. 판정표의 "무료 확인"이 근거보다 강하다. "앱 등록 무료 확인, 카드·정책은 미확인"으로 낮춰야 한다.

## D. 계획의 결함

높음

1. M8 모자이크가 실제로는 가린 정보를 지우지 못한다. plan.md:83은 결과를 `flat`에 굽는다고 하지만,
   * 촬영 원본 `src_<id>.jpg`가 그대로 남는다(storage.dart:34 주석, :144~152). 윤곽 수정(재펴기)으로 새 페이지를 만들면 원본에서 다시 만들어 모자이크가 사라진다(HANDOFF.md:40의 마스크와 같은 구조).
   * 자동 정리 후 모자이크를 하면, 정리를 다시 눌러 끌 때 `p.flat = p.rawFlat!`(editor_screen.dart:118)로 모자이크 전 이미지가 돌아온다.
   * 7단계 백업 ZIP은 `src_`까지 담는다(plan.md:124 "doc.json+사진"). 가린 원본이 백업 파일로 밖에 나간다.
   * 합격 기준(plan.md:83)은 출력 이미지와 OCR만 본다. 원본·rawFlat·백업에 가린 정보가 남지 않는다는 기준이 없다.
   고칠 것: 모자이크 시 src·rawFlat에도 같은 영역을 굽거나 그 페이지의 재펴기·정리 되돌리기를 막는 설계, 그리고 "모든 저장 파일에서 영역 픽셀 변화" 기준.
2. M3 주석을 서명 스탬프에 얹으면 영역 자르기 때 모두 지워진다. editor_screen.dart:223~226이 자를 때 `p.stamps.clear()`로 서명을 지운다. plan.md:82는 위험을 "위치 어긋남"으로만 적었다. 실제는 데이터 손실이다. 기울기 보정 후 ±6° 어긋남도 미수정(HANDOFF.md:66). 합격 기준 "회전 후에도 맞음"에 자르기·기울기 보정이 빠졌다.
3. 데이터 안전장치가 맨 뒤다. 1·3단계가 doc.json과 flat을 바꾸는데 백업·복원은 7단계(plan.md:117)다. 저장 코드는 doc.json을 아는 필드만으로 새로 쓰고(storage.dart:191~221), `keep`에 없는 파일은 지운다(storage.dart:225~229). 새 필드·새 파일을 load와 save 양쪽에 다 넣지 않으면 조용히 사라진다. 이 위험이 plan.md 어디에도 없다. 백업·복원을 1단계 앞(또는 1단계)으로 옮기고, 각 단계 끝 조건에 "옛 문서 열기 → 저장 → 다시 열기 왕복에서 필드·파일 보존"을 넣어야 한다.
4. P9 비밀폴더 우회 경로가 정의되지 않았다. plan.md:123 합격 기준 "어디에도 안 보임"의 '어디'가 없다. 확인할 것: 백업 ZIP(잠긴 문서 포함 여부와 암호가 "권장"으로만 남음, plan.md:124), 안드로이드 최근 앱 화면 미리보기(FLAG_SECURE 언급 없음), 폴더 칩 개수·문서 수 표시, 공유 시트, 안드로이드 자동 백업(매니페스트에 `allowBackup` 지정 없음, AndroidManifest.xml:6, 기본값은 켜짐). 하나라도 새면 잠금이 겉치레가 된다.
