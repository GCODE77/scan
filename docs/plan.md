## 승인 게이트

* 오너가 이 문서를 승인하기 전에는 구현을 시작하지 않는다. 앱 소스(`lib/`, `android/`, `pubspec.yaml`)는 승인 전까지 한 줄도 고치지 않는다.
* 승인은 단계별로 받을 수 있다. 0~11단계(온디바이스)와 12단계(외부 서비스 격상 후보)는 따로 승인한다. 12단계는 오너가 서비스 계정·앱 등록을 직접 마친 뒤에만 시작한다.
* 아래 "오너 결정 필요"의 답이 없는 단계는 시작하지 않는다(각 단계에 필요한 결정 번호를 적었다).
* 승인 상태: **승인** (2026-11-16, 오너 "제안대로 승인": 0~11단계와 Q1~Q14 모두 담당 제안대로. 12단계는 계정 등록 후 별도 승인). 문서 v3, 독립 채점 2회로 종료, 이후 기계 검사만

## 전체 제약

1. 운영 서버가 없다. 앱은 오프라인 우선이고 모든 처리는 폰 안에서 한다. 무료 서버는 허용하지만 유료이거나 비용이 발생할 수 있는 것(유료 API, 유료 플랜, 사용량 과금, 초과 시 과금될 수 있게 카드를 등록해야 하는 서비스)은 쓰지 않는다.
2. 개인 앱(오너 한 명). 배포는 GitHub 릴리스(GCODE77/scan)에 `BookScan.apk`를 올리면 앱이 스스로 업데이트한다. 서명은 기존 debug 키 그대로(HANDOFF.md §4).
3. 현재 APK 70,855,315바이트(67.6MiB). 의존성을 추가할 때마다 APK 증가량을 적고, 추정이면 추정이라고 쓴다. 단계마다 실제 APK 크기를 바이트로 progress.md에 기록하고, 오너가 정한 상한(결정 Q9)을 넘으면 그 단계는 배포하지 않는다.
4. OpenCV는 core·imgproc·imgcodecs만. photo 모듈을 쓰는 설계는 하지 않는다(HANDOFF.md §3).
5. minSdk 24. 새 패키지는 minSdk 24 이하를 요구해야 한다.
6. 프로젝트 경로에 한글이 있어 빌드·분석은 ASCII 복사본(`.../scan_build`, `.../scan_chk`)에서만 한다(HANDOFF.md §4). 빌드는 12분~1시간.
7. 폰 실기기에서만 확인되는 것(ML Kit 모델 다운로드, 제스처, 인쇄 대화상자, 생체인증 창, OAuth 로그인 창, 공유 시트 대상 앱, 최근 앱 미리보기, 저장 창 스트림 쓰기)은 PC에서 검증했다고 쓰지 않는다.
8. PC 검증은 두 종류로 나눠 적는다. (가) Dart 코드 자체: `dart analyze`와, OpenCV·플랫폼을 부르지 않는 순수 Dart 함수의 `flutter test`. (나) Python 이식본: 알고리즘을 Python OpenCV로 옮겨 검증한 것. 이것은 Dart 구현이 맞다는 증거가 아니다(HANDOFF.md §4, PC에서 Dart의 OpenCV 경로는 못 돌림).
9. 클릭 수를 줄이는 동선. 앱 안 알림·오류는 읽을 수 있는 한국어 문장으로 쓰고 내부 오류 코드를 그대로 띄우지 않는다.
10. 저장 구조 규칙. doc.json을 쓰는 경로는 세 곳이다.
    * `Store._save`: 아는 필드만 doc.json에 쓰고(storage.dart:191~226), 임시 파일에 쓴 뒤 바꿔치기(:228~230), `keep`에 없는 파일은 지운다(:147, :233~236).
    * `Store.setFolder`(storage.dart:278~286): `_save`를 거치지 않고 doc.json을 직접 고쳐 쓴다. 바꿔치기 없이 바로 쓰고(:284), 저장 줄을 기다리기만 하고 자기 쓰기는 줄에 넣지 않는다(:279).
    * `Store.shrinkOriginals`(storage.dart:312~357, main.dart:134에서 호출): 원본을 줄이고 doc.json을 바로 쓴다(:355).
    새 필드는 저장·불러오기 양쪽에, 새 파일은 저장·불러오기·`keep` 세 곳에 넣는다. 새 필드는 있을 때만 기록하고 없으면 기본값. 여러 문서를 한꺼번에 고치는 기능(태그 등)은 `setFolder` 방식을 따라 하지 않고, 2단계에서 정리한 저장 줄 경로를 쓴다.
11. 에이전트는 외부 서비스 계정을 만들거나 로그인·키 발급을 할 수 없다.
12. 한글이 섞인 코드 수정은 Edit 도구로, 개행(CRLF/LF) 유지(HANDOFF.md §4).
13. 안드로이드는 같은 서명이라도 낮은 버전으로 덮어 설치가 안 된다. 업데이트가 문서를 망가뜨리면 되돌리는 길은 백업 파일뿐이다. 그래서 저장 코드를 건드리지 않는 백업·복원(1단계)을 먼저 배포하고, 저장 코드를 바꾸는 일은 그다음 릴리스부터 한다.

### 1단계 v0.29.0: 백업·복원 (저장 코드는 건드리지 않음)

먼저 하는 까닭: 전체 제약 13. 이 릴리스는 `Store._save`·`load`·`setFolder`·`shrinkOriginals`를 고치지 않는다. 문서 폴더를 있는 그대로 읽어 묶기만 한다. 필요한 결정: Q13(저장 경로). Q1은 시작 시점만 정한다(0단계를 먼저 하기로 하면 0단계 뒤).

저장 경로 문제: 지금 저장 창 `FilePicker.saveFile`(save_sheet.dart:484)은 file_picker 13.1.0에서 `required Uint8List bytes`(file_picker.dart:169~171)이고, 안드로이드 구현은 바이트 전체를 메서드 채널로 넘긴다(리뷰어가 android_file_picker 2.1.1 file_picker_android.dart:229~257 확인). ZIP을 임시 파일로 만들어도 이 경로로는 전체를 메모리에 올려야 한다.

| 안 | 내용 | 장점 | 단점 | APK |
